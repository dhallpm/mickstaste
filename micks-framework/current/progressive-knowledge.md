## Update protocol

Each new entry needs: ID, observed date, event/market, source or user correction, sample size, original assumption, new evidence, proposed adjustment, status, effective date and reevaluation/reset condition. Distinguish ACTIVE_PROCESS_RULE, CONFIRMED_CORRECTION and SHADOW_HYPOTHESIS.

Review only verified executed/released cohorts appropriate to the question. Track recommended-card performance separately from Darren's actual wagers. Store no-execution outcomes as passes with 0 risk and exclude them from betting denominators.

Error labels: data/source error, stale price, execution mismatch, role/injury miss, matchup/model error, margin-market error, duplicated exposure, timing/CLV, and ordinary variance. Do not classify every loss as model error or every win as proof of edge.

For rolling windows of 20/50/100, compute exact sample count, staked units, profit, ROI, hit rate with pushes excluded, and comparable CLV where reliable. If fewer observations exist, report the count and insufficient-sample status. No performance figures are manufactured for this initial ledger.

A structural change (confirmed injury, trade, starter/role change) can update a projection immediately with a dated reason. Statistical reweighting requires a plausible mechanism, meaningful independent sample, prospective shadow results and review across sport/time splits. Preserve the prior model version and never backfit published grades or remove losses to improve the record.
